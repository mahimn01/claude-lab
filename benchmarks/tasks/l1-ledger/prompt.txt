Add multi-currency support to the ledger package in this folder. Keep the existing behaviour working and keep the existing tests passing. Requirements:

1. models.Transaction gets a new last field `currency` (str, default "USD").
2. parser.parse_csv accepts an optional `currency` column. A missing column or an empty value means "USD". Otherwise the value is stripped, uppercased, and must be exactly three ASCII letters; anything else raises ValueError("bad currency on line N") (N counts the header as line 1, as for the other row errors).
3. New module ledger/rates.py with `class UnknownCurrency(ValueError)` and `convert(amount, currency, base, rates)`. `rates` maps an uppercase currency code to the value of one unit of it in USD; USD is always 1 and does not need to be listed. The result is amount * rates[currency] / rates[base], quantized to Decimal("0.01") with ROUND_HALF_UP. If currency == base, return amount unchanged (no rounding). A currency or base that is neither USD nor in `rates` raises UnknownCurrency(code), whose message is just the code.
4. report.py: `total`, `monthly_totals` take optional `rates=None, base="USD"` and convert every transaction with convert() before summing (rates=None behaves as an empty mapping, so a non-USD transaction then raises UnknownCurrency). Add `category_totals(transactions, rates=None, base="USD")` returning a dict category -> Decimal, with an empty category reported as "uncategorized", ordered by total descending and by category name ascending on ties.
5. cli.main(argv, text) accepts `--by-category` (print category lines instead of monthly lines, same "name: amount" format, then the TOTAL line), `--base CODE` (default USD, case-insensitive) and `--rate CODE=VALUE`, which may be repeated (CODE is case-insensitive, VALUE a Decimal greater than zero), and `--format FORMAT` where FORMAT is `text` (the default, the current output) or `csv` (case-sensitive). CSV output is a header line `month,amount` (`category,amount` with --by-category), one `name,amount` line per row, then `TOTAL,amount`, written with the csv module's default quoting (QUOTE_MINIMAL) and lineterminator "\n", joined with "\n" and with no trailing newline. Amounts are shown in the base currency with two decimals. Errors return (2, "error: ...") with these messages: `error: unexpected argument X` for an unknown argument, `error: missing value for OPTION` when --base, --rate or --format has no value, `error: bad format VALUE` for any other --format value, `error: bad rate ARG` when a --rate value is not CODE=VALUE or not a positive decimal (ARG is the argument text as given), and `error: unknown currency CODE` when UnknownCurrency is raised. Existing errors keep their text.

Add tests for the new behaviour to test_ledger.py and make sure the whole test suite passes.
